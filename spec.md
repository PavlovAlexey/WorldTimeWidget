# WorldTimeWidget — техническая спецификация реализации

**Дата:** 2026-09-14
**Статус:** к реализации
**Дизайн:** см. [design_brief.md](design_brief.md) (текстовое описание) и сам файл в Penpot — `http://localhost:9001`, файл с бордами, страница «WorldTimeWidget — дизайн (Fluent/Mica)», 5 артбордов (01 · Основной вид, 02 · Наведение курсора, 03 · Добавление города, 04 · Режим редактирования списка, 05 · Меню). Все цвета/радиусы/тени/шрифты — из этого дизайна, см. раздел «Результат отрисовки» в design_brief.md для точных значений (surface `#F3F3F3 @78–94%`, accent `#0078D4`, textPrimary `#1B1B1B`, textSecondary `#6B6B6B`, divider `#000000 @6%`, радиус 8px/6px, drop-shadow blur 24–28 offsetY 8–10 чёрный 16–20%). Вместо Segoe UI (недоступен в самохостинге Penpot) в макете стоит Inter — в реализации использовать системный **Segoe UI Variable** (доступен из коробки на Windows).

## Стек и требования платформы

- **.NET 8, WPF**, `net8.0-windows`, только Windows (используем WinAPI-специфику: registry autostart, DWM/acrylic).
- Сборка **self-contained single-file** под `win-x64`, чтобы результат запускался на чужом ПК без установленного .NET Runtime:
  `dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true`
- Инсталлятор: **Inno Setup** — один exe-установщик, устанавливает per-user (без прав администратора) в `%LocalAppData%\Programs\WorldTimeWidget`, создаёт ярлык в Пуске (+ опционально на рабочем столе), корректно прописывает деинсталлятор.
- Репозиторий/файлы кладём в `C:\cfgs\WorldTimeWidget\` (сейчас там только `design_brief.md` и этот файл): решение `WorldTimeWidget.sln`, проект `src/WorldTimeWidget/`, инсталлятор `installer/WorldTimeWidget.iss`, `README.md` с инструкцией сборки/публикации/установки.

## Функциональность

### Окно виджета (главный экран)
- Плавающее окно без рамки: `WindowStyle="None"`, `AllowsTransparency="True"`, `ShowInTaskbar="False"`, без иконки в панели задач и без системного трея (по решению из дизайна — только floating widget).
- Перетаскивание мышью за любую пустую область карточки (`DragMove()` по `MouseLeftButtonDown`, кроме кликов по интерактивным элементам).
- **Режим «поверх всех окон» — обязательно**: свойство `Topmost`, управляется тумблером в меню «Всегда поверх окон» (см. борд 05), **по умолчанию включено**. Переключение должно применяться сразу, без перезапуска, и сохраняться в настройках между запусками.
- Позиция окна на экране запоминается между запусками (сохранять X/Y в настройках при перемещении/закрытии).
- Список часовых поясов — вертикальные строки как на борде 01: слева индикатор день/ночь (точка) + название города, под ним дата в этом часовом поясе; справа крупное время + строка `UTC±N`. Домашний (системный, `TimeZoneInfo.Local`) часовой пояс всегда первой строкой, визуально подсвечен (полупрозрачная плашка), **не может быть удалён и не участвует в ручном перетаскивании порядка**.
- Индикатор день/ночь: точка тёплого цвета (amber, `#FFB900`) для локального часа 06:00–21:59 в этом поясе, индиго (`#5B5FC7`) для 22:00–05:59.
- Время в списке обновляется вживую: таймер выравнивается на границу минуты и тикает раз в минуту (не каждую секунду — отображаются только часы:минуты, секунды не нужны).
- При наведении курсора на карточку (только когда не в режиме редактирования) в правом верхнем углу появляются две круглые кнопки — «+» (открыть панель добавления города) и «⋯» (открыть меню) — борд 02.

### Добавление города (борд 03)
- Отдельная всплывающая панель (WPF `Popup`, привязана к главному окну, тот же визуальный стиль карточки) с полем поиска сверху и списком результатов (город, страна, `UTC±N`).
- Источник данных: статический курируемый список городов (≈50–80 популярных: столицы + крупные деловые центры), каждый замаплен на .NET `TimeZoneInfo.Id` (Windows time zone id, например «Russian Standard Time» для Москвы, «Tokyo Standard Time» для Токио). Поиск — по подстроке в названии города (регистронезависимо, поддержка кириллицы и латиницы, если разумно ограничиться одним языком UI — используем русский, как в дизайне).
- Клик по результату — добавляет город в список (если ещё не добавлен) и закрывает панель.
- Уже добавленные города не должны предлагаться повторно (либо скрываются из результатов, либо помечаются как «уже добавлен»).

### Режим редактирования списка (борд 04)
- Переключается через пункт меню «Изменить список». В этом режиме каждая (не домашняя) строка показывает слева хваталку (drag handle, иконка из точек) вместо индикатора день/ночь, справа — кнопку удаления «×» вместо времени.
- Перетаскивание строк мышью меняет порядок в списке (порядок сохраняется в настройках). Не обязательно делать анимацию pixel-perfect как в дизайн-тулах — достаточно рабочего reorder по drag (например, через `PreviewMouseMove` + `ObservableCollection` reindex), критерий приёмки — функциональность, а не плавность анимации.
- Внизу списка — пунктирная ghost-кнопка «+ Добавить город», открывающая ту же панель добавления, что и борд 03.
- Выход из режима редактирования — повторным пунктом меню («Готово»/тот же пункт меню переключателем) или кликом вне карточки.

### Меню «⋯» (борд 05)
Пункты сверху вниз, как в дизайне:
1. «Добавить город» — открывает панель добавления (борд 03).
2. «Изменить список» — включает режим редактирования (борд 04).
3. «Формат времени» с текущим значением («24ч»/«12ч») и шевроном — клик переключает между 24-часовым и 12-часовым форматом (простой toggle по клику, без необходимости в дополнительном подменю). Применяется сразу ко всем строкам, сохраняется в настройках.
4. Разделитель.
5. «Всегда поверх окон» — тумблер, управляет `Topmost` (см. выше), по умолчанию включён.
6. «Запуск при входе в Windows» — тумблер, включает/выключает автозапуск через ключ реестра `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` (per-user, без прав администратора). По умолчанию выключен.
7. Разделитель.
8. «Выход» (акцентный красный) — завершает приложение (`Application.Current.Shutdown()`). Это единственный способ закрыть приложение, так как нет ни рамки с крестиком, ни иконки в трее.

### Хранение настроек
- JSON-файл в `%AppData%\WorldTimeWidget\settings.json`: список добавленных `TimeZoneInfo.Id` в порядке отображения, формат времени (24/12), состояние «поверх всех окон», состояние автозапуска, последняя позиция окна (X/Y).
- При первом запуске (файла нет) — список городов пуст (кроме домашнего), Topmost=true, автозапуск=false, формат=24ч, окно по центру-справа основного экрана.

## Визуальное соответствие дизайну
- Точное совпадение цветов/радиусов/типографики — обязательное (значения зафиксированы в design_brief.md и в самом Penpot-файле, сверяться с ним).
- Эффект Mica/acrylic (полупрозрачность с блюром рабочего стола под окном) — если в разумные сроки реализуется через `DWM`/`Windows.UI.Composition` интероп — хорошо, это соответствует духу Fluent; если сложно/нестабильно на WPF — допустим fallback на просто полупрозрачную заливку без блюра фона (как статичный цвет с alpha), это **не блокирует приёмку**, но должно быть явно отмечено в отчёте как компромисс.
- Тени, скругления, отступы — по значениям из дизайна.

## Доработка v1.3 (2026-09-15) — система тем оформления

Пользователь попросил добавить несколько популярных тем оформления виджета (обязательно Windows и Liquid Glass, плюс ещё четыре по согласованию). Дизайн всех 6 тем отрисован и утверждён в Penpot — страница **«Темы виджета — сравнение»** в том же файле, что и остальные экраны (`http://localhost:9001`). Там же наглядно видно, как Liquid Glass просвечивает фон позади себя (отдельный проверочный кроп на той же странице/в истории диалога с тимлидом).

Версию поднять до **1.3.0**.

### Токены тем (точные значения из утверждённого дизайна)

Все цвета — hex, все opacity — доля от 1. `radius` — px (борд-радиус основной карточки и попапов). `homeHighlight`/`homeHighlightOpacity` — заливка подсветки домашней строки (её радиус = `radius - 2`, но не меньше 2px). `dayDot`/`nightDot` — одинаковые во всех темах: `#FFB900` / `#5B5FC7` (сохраняем для узнаваемости индикатора вне зависимости от темы). Шрифт остаётся Segoe UI Variable (с фолбэком Segoe UI) во всех темах, кроме отдельной оговорки для Rainmeter ниже — тема НЕ меняет шрифт, только цвета/форму/тени.

1. **Windows (Fluent / Mica)** — тема по умолчанию, совпадает с текущей реализацией:
   `surface #F3F3F3`, `defaultOpacity 78%`, `border #FFFFFF@60%` (1px), `shadow` чёрная (blur 24, offsetY 8, 16%), `radius 8`, `homeHighlight #FFFFFF@45%`, `textPrimary #1B1B1B`, `textSecondary #6B6B6B`, `divider #000000@6%`, `popupOpacity 94%`.

2. **Liquid Glass** — стилизованное приближение (без настоящего динамического рефракшна, см. обсуждение с тимлидом):
   `surface #FFFFFF`, `defaultOpacity 32%`, `border #FFFFFF@85%` (1.5px), `shadow` чёрная, крупная и мягкая (blur 36, offsetY 14, 22%), `radius 22`, `homeHighlight #FFFFFF@35%`, `textPrimary #1C1C1E`, `textSecondary #5B5B60`, `divider #FFFFFF@50%`, `popupOpacity 55%`.
   Дополнительно: полупрозрачный глянцевый блик — прямоугольник на всю ширину карточки, высотой ~90px, залит `#FFFFFF@18%`, скруглён только сверху (радиус карточки), прижат к верхнему краю, поверх контента (абсолютное позиционирование внутри карточки, не часть flex-потока). Виден только когда активна эта тема.

3. **macOS-виджет** — референс: встроенный виджет «Мировые часы» в Центре уведомлений macOS:
   `surface #FFFFFF`, `defaultOpacity 88%`, `border #000000@6%` (1px, едва заметная грань), `shadow` чёрная мягкая (blur 20, offsetY 6, 14%), `radius 16`, `homeHighlight #007AFF@10%` (системный синий), `textPrimary #1D1D1F`, `textSecondary #86868B`, `divider #000000@8%`, `popupOpacity 96%`.

4. **AMOLED Dark**:
   `surface #000000`, `defaultOpacity 92%`, `border #00E5FF@25%` (1px, неоновая обводка), `shadow` — не чёрная, а неоновая (`color #00E5FF`, blur 24, offsetY 0, 35%) — свечение вместо обычной тени, `radius 10`, `homeHighlight #FFFFFF@8%`, `textPrimary #FFFFFF`, `textSecondary #9A9AA0`, `divider #FFFFFF@10%`, `popupOpacity 96%`.

5. **Minimal Flat**:
   `surface #F5F5F5`, `defaultOpacity 100%` (**слайдер «Прозрачность» для этой темы заблокирован/задизейблен** — плоский дизайн принципиально непрозрачен), `border #000000@14%` (1px), **тени нет вообще** (`shadow: null` — не просто прозрачная тень, а полное отсутствие эффекта), `radius 4`, `homeHighlight #000000@5%`, `textPrimary #111111`, `textSecondary #6B6B6B`, `divider #000000@10%`, `popupOpacity 100%`.

6. **Rainmeter Enigma-style** — референс: культовый скин Enigma, дефолтный скин Rainmeter с 2009 года ([rainmeterui.com/skin/enigma](https://rainmeterui.com/skin/enigma/)):
   `surface #0B0B0B`, `defaultOpacity 85%`, `border #2FB5A0@35%` (1px, тонкая бирюзовая волосяная линия), `shadow` чёрная едва заметная (blur 16, offsetY 4, 30%), `radius 2` (острые углы), `homeHighlight #FFFFFF@6%`, `textPrimary #E8E8E8`, `textSecondary #7A7A7A`, `divider #FFFFFF@8%`, `popupOpacity 92%`.
   Отличие в типографике: название города рисуется начертанием **Regular** вместо Medium (более утилитарный/HUD-вид), остальные размеры шрифта — как везде.

### Архитектура

- Диапазон слайдера «Прозрачность» расширить с текущего 40–100% до **20–100%** (`MainViewModel.MinBackgroundOpacityPercent = 20`) — иначе дефолт Liquid Glass (32%) не влезает в текущий диапазон.
- **Прозрачность теперь хранится отдельно на каждую тему**, а не одним общим числом: `AppSettings.BackgroundOpacityByTheme: Dictionary<string, int>` (ключ — id темы). При первом переключении на тему, для которой ещё нет сохранённого значения, используется её `defaultOpacity` из токенов выше. Слайдер в меню всегда показывает/меняет значение для **текущей активной** темы, не трогая сохранённые значения остальных тем.
- Новая настройка `AppSettings.ThemeId` (string, дефолт `"windows"`), персистится, применяется сразу при переключении (live, без перезапуска) — по аналогии с тем, как уже работает `Is24HourFormat`/`IsAlwaysOnTop`.
- Текущий подход с мутируемой на месте `SolidColorBrush` (см. `CardBackgroundBrush` в `MainViewModel`) — расширить на **все** цветовые токены темы (border, shadow color, home-highlight, текст, divider), заведя их как bindable-свойства/кисти на `MainViewModel` (или отдельном `ThemeViewModel`/`ThemeService`), а не статические ресурсы в `Colors.xaml`. `Colors.xaml`/`Controls.xaml` при этом не обязательно выкидывать целиком — статичными могут оставаться вещи, не зависящие от темы (размеры, отступы, шрифт), но всё, что перечислено в токенах выше, должно стать переключаемым.
- `CornerRadius` (карточка, попапы, домашняя строка) и параметры `DropShadowEffect` (`Color`, `BlurRadius`, `ShadowDepth`, `Opacity`) — не кисти, а обычные свойства; их тоже нужно забиндить на текущую тему (через `{Binding}` в XAML на dependency-свойствах `DropShadowEffect`, которые вполне поддерживают биндинг).
- Попапы (`AddCityView`, `MenuView`) сейчас используют фиксированный `SurfaceStrongBrush` — перевести на тему активной темы с её собственным `popupOpacity` (см. токены выше), а не на слайдер «Прозрачность» (тот управляет только основной карточкой, как и раньше).
- Глянцевый блик Liquid Glass — реализовать как элемент, видимый только при `ThemeId == "liquid-glass"` (Opacity/Visibility по условию, не через физическое добавление/удаление, см. уже устоявшийся в проекте паттерн с Opacity/IsHitTestVisible вместо Visibility для мгновенно показываемых/скрываемых элементов).

### UI переключения темы

- Новый пункт в меню «⋯» — «Тема»: сетка из 6 круглых/скруглённых свашей (32×32px, отступы 8px, 3 в ряд × 2 ряда — под ширину меню 230px), залитых `surface`-цветом соответствующей темы, с тонкой обводкой её `border`-цвета. У активной темы — акцентное кольцо/обводка потолще (2px) вокруг сваша как индикатор выбора. Клик — мгновенно переключает тему (включая пересчёт прозрачности карточки на сохранённое/дефолтное значение для этой темы, форму радиусов, тени, попапы).
- Порядок сваши слева направо/сверху вниз — как в списке токенов выше (Windows, Liquid Glass, macOS, AMOLED Dark, Minimal Flat, Rainmeter Enigma).
- Когда активна Minimal Flat — слайдер «Прозрачность» показывается задизейбленным (серым, неактивным), с текущим значением 100%, чтобы было явно видно, что для этой темы прозрачность недоступна принципиально, а не просто забыли её выставить.

## Доработка v1.1 (2026-09-14) — обратная связь после релиза v1.0.0

Пользователь пользуется готовым виджетом и просит два точечных изменения. Версию бампнуть до **1.1.0** (csproj: `Version`/`FileVersion`/`AssemblyVersion`; `installer/WorldTimeWidget.iss`: `MyAppVersion`).

### 1. Настраиваемая прозрачность виджета

- Новая настройка `BackgroundOpacityPercent` (int, диапазон **40–100**, шаг 1) в `AppSettings` — персистится в `settings.json`, как и остальные настройки. Дефолт — текущее значение прозрачности карточки (сейчас зашито как `#E0F3F3F3`, т.е. альфа `0xE0` ≈ **88%** — используй именно 88 как дефолт, чтобы для существующих пользователей без settings.json внешний вид не изменился).
- Управляется **слайдером** в меню «⋯» — подпись «Прозрачность» + текущее значение в процентах (например, «Прозрачность 82%»), обновляется вживую при перетаскивании. Разместить в группе с «Формат времени» (после него, до разделителя перед тумблерами «Всегда поверх окон»/автозапуск). Нужен новый стиль слайдера в `Themes/Controls.xaml` в общей Fluent-стилистике (тонкий трек, заливка трека акцентным цветом слева от ползунка, круглый thumb) — по аналогии с уже существующим `ToggleSwitchStyle`.
- **Область действия**: слайдер регулирует **только альфа-канал фона основной карточки** (`RootBorder.Background`, т.е. по сути `SurfaceBrush`). Всплывающие панели (добавление города, само меню «⋯») **не трогать** — у них должна остаться текущая фиксированная непрозрачность (`SurfaceStrongBrush`), так как это временные оверлеи и читаемость там важнее прозрачности. Текст, иконки, индикаторы день/ночь — всегда полностью непрозрачны (100%), слайдер не должен на них влиять никаким образом.
- Реализация: скорее всего `SolidColorBrush`, чей альфа-байт пересчитывается из настройки (или `Binding` с конвертером `int (0-100) → byte альфа` на цвет `#F3F3F3`), обновляется сразу при движении слайдера и сохраняется в settings.json (как и другие настройки в проекте — сохранение при каждом изменении, без отдельной кнопки «Применить»).

### 2. Hover-кнопки "+"/"⋯" перекрывают текст первой строки

Пользователь сообщил, что в текущей сборке круглые кнопки "+" и "⋯", всплывающие по наведению курсора в правом верхнем углу карточки (борд 02), **перекрывают буквы** — визуально накладываются на название/время домашней строки. Нужно поднять кнопки выше, чтобы они не пересекались с текстом ни в одном состоянии:
- обычный hover (обе кнопки видны);
- hover в режиме редактирования (видна только "⋯", "+" скрыта — см. текущую логику в `MainWindow.xaml.cs`/`MainViewModel.IsEditMode`).

Способ реализации на усмотрение разработчика (например: зарезервировать небольшой отступ сверху карточки под кнопки, чтобы они всегда лежали в чистой зоне над текстом первой строки, не наезжая на неё; либо уменьшить/сместить кнопки так, чтобы они укладывались в существующий верхний padding без пересечения с текстом). Ограничение: домашняя строка (первая, с подсветкой) не должна визуально "прыгать"/менять высоту при наведении — если для клиренса кнопок используется постоянный отступ сверху карточки, он должен быть на месте всегда (и при наведении, и без), а не появляться только по hover, чтобы не было дёргания layout.

**Критерий приёмки**: сделай скриншот (или несколько) наведённого состояния карточки (обычный режим и режим редактирования) с добавленными городами так, чтобы в кадре была домашняя строка — визуально подтверди, что круглые кнопки не накладываются на текст названия города/времени. Приложи скриншот(ы) в отчёте.

## Доработка v1.2 (2026-09-15) — трей-иконка + «прозрачность для кликов»

Пользователь спросил про режим, при котором клики проходят «сквозь» виджет к окнам под ним (click-through). Обсудили: технически это `WS_EX_TRANSPARENT` (WinAPI extended window style), но проблема — включив его, виджет перестаёт получать вообще любые клики, включая по своим кнопкам, и штатно выключить режим обратно через меню виджета нельзя. Договорились с пользователем, что решение — **добавить иконку в системный трей**: она не зависит от click-through/скрытия окна и всегда остаётся кликабельной, то есть служит гарантированным «предохранителем».

Версию поднять до **1.2.0** (csproj + `.iss`, по аналогии с v1.1).

### 1. Иконка в трее

- `NotifyIcon` (`System.Windows.Forms`) — в csproj рядом с `<UseWPF>true</UseWPF>` добавить `<UseWindowsForms>true</UseWindowsForms>` (стандартный, широко используемый способ добавить трей-иконку в WPF-приложение без сторонних NuGet-пакетов; в проекте и так принцип «ноль внешних зависимостей», см. `RelayCommand`). Иконка — тот же `Assets/app.ico`, подсказка (tooltip) — «WorldTimeWidget».
- Живёт на уровне приложения (создаётся/освобождается в `App.xaml.cs`), не привязана к жизненному циклу `MainWindow`.
- **Двойной клик по иконке** — переключает видимость окна виджета (`Window.Visibility` Hidden/Visible). Видимость **не персистится** между запусками — при каждом старте приложения виджет показывается сразу (чтобы не было ситуации «запустился, а найти виджет через скрытый+click-through режим не могу»).
- **Правый клик** — контекстное меню (`ContextMenuStrip`), пункты сверху вниз:
  1. «Показать виджет» / «Скрыть виджет» (подпись зависит от текущей видимости — по аналогии с тем, как `EditModeMenuLabel` меняет подпись «Изменить список»/«Готово»).
  2. «Прозрачный для кликов» — чекбокс (checkable menu item), состояние = `IsClickThrough` (см. ниже).
  3. «Всегда поверх окон» — чекбокс, зеркалит существующий `IsAlwaysOnTop` (тот же источник истины, что и тумблер в меню «⋯» — переключение в любом из двух мест должно немедленно отражаться в другом).
  4. Разделитель.
  5. «Выход» — тот же `ExitCommand`, что и в меню «⋯».
  - `ContextMenuStrip` в WinForms не биндится декларативно как WPF — обнови состояние чекбоксов вручную по событию `Opening` контекстного меню (прочитать текущие значения `IsClickThrough`/`IsAlwaysOnTop`/видимости перед показом).

### 2. Настройка «Прозрачный для кликов» (click-through)

- Новая настройка `IsClickThrough` (bool, дефолт `false`) в `AppSettings`, персистится в `settings.json`, как остальные.
- Включение/выключение — через WinAPI `GetWindowLongPtr`/`SetWindowLongPtr` с флагом `WS_EX_TRANSPARENT` на `hwnd` главного окна (окно уже `AllowsTransparency="True"`, т.е. WPF уже проставил `WS_EX_LAYERED` — просто добавляем/убираем `WS_EX_TRANSPARENT` поверх текущих extended styles, не перезаписывая их целиком).
- Когда включено — окно виджета полностью не реагирует на мышь (клики проваливаются к тому, что под ним): это ожидаемо и нормально, включая то, что hover-кнопки/drag/меню виджета становятся недоступны, пока режим включён. **Единственный способ выключить обратно — трей** (правый клик → снять галочку «Прозрачный для кликов»), либо предварительно (пока ещё выключено) — тумблер в меню «⋯» (аналогичный `ToggleSwitchStyle`, как «Всегда поверх окон»), но раз включив через меню, для выключения обратно тоже придётся идти через трей — это ожидаемое поведение, отразить в README.
- Обязательно проверить (и явно описать в отчёте, это критичный момент): **при включённом click-through трей остаётся полностью рабочим**, и через него можно как минимум выключить click-through обратно и корректно выйти из приложения. Без этой гарантии фича не принимается.
